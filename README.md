# LocalizedTool — 网页版游戏本地化流程工具

借助大模型完成游戏本地化的完整流程：**术语提取 → 模型翻译 → 翻译校验**。
支持多用户、项目权限隔离，每个用户使用自己配置的大模型（OpenAI 兼容协议）。

## 功能总览

| 功能 | 说明 |
|---|---|
| 用户管理 | 管理员创建用户、创建项目、分配项目权限；用户右上角常驻设置，自配大模型地址/模型名称/Token（Token 加密存储，前端不可见），支持测试连接 |
| 术语提取 | 上传 Excel → 选源语言列 → 大模型分批提取术语 → 逐条/批量确认写入项目术语库；术语库可上传覆盖（二次确认）与下载 |
| 模型翻译 | 术语未全语种翻译时弹窗提醒并批量翻译术语；批量翻译遵循术语库、保留代码/占位符、可设字符上限；进度条 + 前 50 行预览 + 全量 Excel 下载 |
| 翻译校验 | 复用成熟 LQA 校验器：翻译语言空/他语种、占位符/标签、标点规范、长度限制、术语一致性、数字一致性、转义符、首尾空格、拼写检查共 9 项；按列名自动判定语种、直接使用项目术语库；结果可下载 Excel |

## 快速开始

### Windows

```
双击 setup.bat    # 一键安装环境（需要已装 Python 3.10+）
双击 run.bat      # 启动服务并自动打开浏览器
```

### macOS / Linux

```bash
./setup.sh
./run.sh
```

启动后浏览器访问 `http://127.0.0.1:5000`。

**默认管理员账号：`admin / admin123`**（请登录后及时新建普通用户并分配项目，管理员也可直接操作项目）。

## 使用流程

1. **管理员**登录 → 右上角「设置」→「用户与项目」→ 新建项目（设置源语言列名、目标语种及每个语种的源语言）、新建用户并勾选分配项目。
2. **用户**登录 → 右上角选择项目 → 右上角「设置」→「大模型」填写 Base URL / 模型名 / API Key，点「测试连接」验证。
3. **术语提取**：上传 Excel → 选源语言列 → 开始提取 → 勾选确认术语写入术语库。
4. **模型翻译**：进入页签时若术语未全语种翻译会弹窗提醒；上传文件 → 选源语言列与源列语言 → 勾选目标语种（可设字符上限列）→ 开始翻译 → 预览/下载。
5. **翻译校验**：可直接上传翻译文件，或在翻译页点「校验翻译结果」带入翻译输出；确认源列与语种后点「开始校验」，查看结果并下载。

## 术语库格式

每个项目一个术语库 Excel（`data/projects/<id>/glossary.xlsx`）：

| ID | 中文（源语言列，名称由项目定义） | English | 日本語 | … |
|---|---|---|---|---|
| 1 | 护腕 | Bracer | ブレスレット | … |

- 第一列 `ID` 自动自增。
- 源语言列列名与语种列名由**管理员在创建项目时固定**，且**全部用统一规范的语言下拉选择**（中文(简体)、English、日本語、Deutsch …），Excel 表头、术语库、翻译输出、校验识别都用同一套名字，全项目一致。兼容旧表头别名（如 `中文` 会被识别为 `中文(简体)`）。
- 术语**翻译完整 = 所有语种列均非空**；存在任一语种列为空即为“未翻译”。

## 项目 / 权限模型

- 只有**管理员**能创建用户与项目；用户只能操作被分配的项目，不可跨项目操作。
- 项目语种固定：管理员为每个目标语种指定其源语言（中文或英文），翻译时按项目配置判定源语言，不再需要手动选择「源列语言」。
- 翻译依赖顺序：源语言=中文的语种先翻译，源语言=英文的后翻译。

## 大模型配置说明（OpenAI 兼容）

在「设置 → 大模型」填写：

- **Base URL**：如 `https://api.openai.com/v1`、`https://api.deepseek.com/v1`、通义/智谱等 OpenAI 兼容端点。若地址已含 `/chat/completions` 也可直接使用。
- **模型名称**：如 `gpt-4o`、`deepseek-chat`。
- **API Key / Token**：加密存储于本地 `data/app.db`（密钥在 `data/.secret_key`），任何接口都不会把明文返回给浏览器。

## 翻译 / 提取的规则

- **术语优先**：源文本命中术语库时，翻译结果必定使用术语库译文；术语提取的提示词要求只输出专有名词/反复出现的词组。
- **代码保留**：`{0}`、`%s`、`<color=#fff>`、`\n`、`$var`、`{{x}}` 等占位符/标签/转义符在翻译时原样保留，翻译后自动校验，缺失时自动纠错重试。
- **字符上限**：翻译可针对每个目标语种设置“字符上限列”，超出会提示并自动纠错。
- **分批发送（快）**：每个目标语种尽量用**一次大请求**发送（单批上限 100 行 / 15000 字符），短文本一个语种一个批次；提示词只携带当前批次中真正出现的术语；超时 60s / 连接 10s，慢网络快速失败不空转。批量翻译请使用快速对话模型（如 `deepseek-chat` / `gpt-4o-mini`），避免推理型模型（r1/o1）导致的长时间等待。

## 翻译校验说明

- 校验按**文件列名自动判定语种**：与项目语种同名的列即目标语言列；源列也**自动识别**（优先匹配项目源语言列名，兼容别名），无需手动选择源语言列。
- 术语一致性直接使用**项目术语库**对应语种的列。
- 拼写检查使用**随项目内置的离线词典**（`hunspell_dicts/`，含 de/en/es/fr/it/nl/pl/pt/ru/sv 十种常用语种的 hunspell 词典与词表），**首次使用零下载、零卡顿**，可离线运行。若项目目标语种不在内置集合内，拼写检查会自动降级跳过联网下载（绝不卡顿）；如需为未内置语种自动联网补词典，可设置环境变量 `LOCALIZEDTOOL_WIKI_WORDS=1` 后重启服务。
- 标点检查优先连接本机 LanguageTool（`http://localhost:8081`，可选），无 LanguageTool 时自动使用内置标点规则，不影响其他检查项。

## 数据存储

```
data/
├── app.db                  # 用户/项目/权限/大模型设置（SQLite）
├── .secret_key             # 加密密钥（勿提交 git）
├── uploads/                # 上传的原始文件
└── projects/<project_id>/  # glossary.xlsx 术语库、translations/ 翻译结果、check_results/ 校验结果
```

`data/` 首次运行自动生成，已加入 `.gitignore`。

## 测试

```bash
.venv\Scripts\python.exe -m pytest tests/ -v        # Windows
./.venv/bin/python -m pytest tests/ -v              # macOS/Linux
```

单元测试会打桩大模型（不真实调用 API），覆盖安全、术语库、提取、翻译、校验与全流程。

## 常见问题

- **打开页面一直提示选择项目**：确认账号已被管理员分配了项目。
- **点操作提示先配置大模型**：到右上角「设置 → 大模型」填写并测试连接。
- **端口冲突**：设置环境变量 `PORT=5001` 后启动。
- **浏览器打不开**：直接访问 `http://127.0.0.1:5000`。
